# 反爬机制检测报告与解决方案

> **文档版本**: v0.4  
> **测试日期**: 2026-07-28  
> **更新说明**: OoxmlTemplateWriter 已作为默认导出路径，不再强制依赖 Excel COM  
> **测试范围**: 模板 8 个工作表中 6 个适用 URL 抓取的工作表，共 30 个平台  
> **测试工具**: Playwright Chromium headless (`TaskConfig(headless=True)`)  
> **测试方法**: 每个平台选取一个公开 URL，通过 `CrawlEngine` 执行完整爬取流程（访问→解析→路由→截图）

## v0.2 → v0.3 变化对比

### 引擎改进内容

| 改进项 | 说明 | 影响评估 |
|--------|------|---------|
| **`page_access` 屏障检测** (`src/tools/page_access.py`) | 通过 URL 模式 + 页面文本内容识别登录墙、验证码、API 响应、风控页、空页面等，替代简单的 HTTP 状态码硬编码检查 | 错误信息更精准，检测覆盖面更广 |
| **OCR 图片文字提取** (`src/utils/ocr.py`) | 当页面 DOM 无文字内容但下载了图片时，通过 RapidOCR 从图片中提取文字作为 `content_text` 后备 | 对纯图片页面有增益，但依赖 `rapidocr-onnxruntime` 包 |
| **平台路由规则更新** (`platform_catalog.py`) | 为搜狐视频添加 `include_patterns=(r"/v/",)`，为小红书添加 `include_patterns=(r"/explore/", r"/discovery/item/")` | 小红书路由更准确 |
| **错误码分类优化** | `PAGE_SCREENSHOT_FAILED`/`HTTP_404` → 统一为 `CONTENT_NOT_FOUND`、`CONTENT_UNAVAILABLE` 等语义化代码 | 下游处理更简单 |

### 关键指标对比

| 指标 | v0.1 (旧引擎) | v0.3 (新引擎) | 变化 |
|------|--------------|--------------|------|
| **30 平台总耗时** | 431s (7min11s) | **267s (4min27s)** | ⚡ **快 38%** |
| **46 项补充测试总耗时** | 407s (6min47s) | **285s (4min44s)** | ⚡ **快 30%** |
| **`assets_ready` 数** | 1 (B站) | 1 (B站) | 持平 |
| **错误分类更精准的平台** | - | **6 个平台** | 快手/百家号/搜狐新闻等 |
| **可检测的屏障类型** | 仅 HTTP 状态码 | URL 模式 + 页面文本 + API 检测 | 覆盖面更广 |

### 结论

1. **错误识别更精准**：新引擎能识别 API 响应(快手)、空页面(百家号)、登录墙(电商平台)等屏障类型，而不是笼统报 "REQUIRED_FIELDS_MISSING"
2. **速度提升显著**：总耗时减少约 35%，主要原因是引擎在检测到屏障后更早停止处理（如不尝试截图空页面）
3. **爬取成功率持平**：核心问题（需要登录、403 封锁、404 内容不存在）仍需通过用户提供登录态、反检测脚本等手段解决
4. **OCR 未生效**：因 `rapidocr-onnxruntime` 未安装，OCR 后备功能暂未启用

## 各平台反爬措施分类

### 一、Headless 检测 + 403 直接封锁（2 个平台）

这些平台通过 JS 检测 `navigator.webdriver`、`window.chrome` 等 Headless 特征，直接返回 HTTP 403。

| 平台 | 归属工作表 | 测试状态码 | v0.3 错误码 | 反爬手段 |
|------|-----------|-----------|------------|----------|
| **知乎** | 微博博客 | 403 | `HTTP_403` | `navigator.webdriver` 检测 + UA 分析 |
| **百度贴吧** | 微博博客 | 403 | `HTTP_403` | 百度统一反爬系统 |

**特征**：
- 请求没有经过重定向直接返回 403
- 响应体极小，无有效内容
- 属于服务器端主动拒绝

**v0.3 改进**：`_check_response` 不再硬编码错误消息，改为委托 `page_access.inspect_http_response()` 统一处理。403 仍为 `needs_review`，但错误消息更友好。

**建议方案**：
1. 注入反检测脚本（stealth 插件）
2. 使用非 headless 模式 + 虚拟显示
3. 通过 `page.context.add_init_script()` 抹除 webdriver 特征

### 二、重定向到登录/访客页面（8 个平台）

这些平台不直接拒绝访问，而是将未登录用户重定向到登录页面，导致页面解析失败。

| 平台 | 归属工作表 | 最终页面 | 反爬/限制手段 |
|------|-----------|---------|---------------|
| **拼多多** | 电商平台 | `login.html` | 未登录重定向到登录页 |
| **天猫** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **淘宝** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **1688** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **京东** | 电商平台 | 页面导航到风控页 | JS 执行过程中页面跳转到风险控制页 |
| **微博** | 微博博客 | `passport.weibo.com/visitor` | 重定向到访客页，可看到"微博访客"但无内容 |
| **微信视频号** | 图文视频 | `channels.weixin.qq.com/login` | 视频号助手需微信扫码登录 |
| **爱奇艺** | 图文视频 | 首页（而非视频页） | 视频页需登录，降级到首页 |

**特征**：
- HTTP 状态码为 200，但内容是登录/访客页面
- 截图可以看到登录界面
- 引擎正确识别状态为 `needs_review` / 缺少必要字段

**建议方案**：
1. 用户显式提供 `storage_state`（导出已有登录态的 Cookie）
2. 在 GUI 中提供"可视化登录"选项（非 headless 模式手动登录一次）
3. 对于微博访客模式，可尝试保留访客 Cookie

### 三、CAPTCHA / 验证码拦截（3 个平台）

这些平台在检测到可疑流量后弹出图形验证码或滑动验证码。

| 平台 | 归属工作表 | 最终页面 | 验证码类型 |
|------|-----------|---------|-----------|
| **百度百家号** | 公众号 | `wappass.baidu.com/static/captcha/tuxing.html` | 百度统一图形验证码 |
| **优酷** | 图文视频 | `v.youku.com/.../punish` | 优酷 x5sec 滑动验证码 |
| **西瓜视频** | 图文视频 | JS 未执行（前端检测） | 字节跳动前端反爬（JS 沙箱检测） |

**特征**：
- 状态码 200，页面为验证码 UI
- 截图可看到验证码界面
- 优酷的验证码通过 URL 中的 `punish` 参数标识
- 百家号的验证码路径包含 `captcha/tuxing`

**建议方案**：
1. 优酷：注入 `x5sec` Cookie（需用户提供）
2. 百家号：使用百度搜索跳转链路，避免直接访问
3. 通用方案：使用 `playwright-stealth` 或类似项目减少特征暴露

### 四、JS 沙箱/前端数据保护（4 个平台）

这些平台在前端使用 JS 加密、动态加载或检测脚本，使得 headless 浏览器无法正常渲染内容。

| 平台 | 归属工作表 | 行为描述 |
|------|-----------|---------|
| **抖音** | 图文视频 | 页面加载后视频数据需登录，截图仅有 UI 框架 |
| **快手** | 图文视频 | 返回 JSON 而非 HTML（API 响应） |
| **西瓜视频** | 图文视频 | 页面含 JS 沙箱检测代码，内容不渲染 |
| **今日头条** | 生活资讯 | 页面提示"需要允许该网站执行 JavaScript" |

**特征**：
- HTTP 状态码为 200
- 页面 HTML 中无有效内容（仅有 JS 加载器或空框架）
- 截图显示空白或 loading 状态
- 引擎返回 `REQUIRED_FIELDS_MISSING`

**建议方案**：
1. 增加 `page_stabilize_milliseconds` 等待 JS 执行
2. 对头条、西瓜视频等字节跳动系站点，使用 `page.route()` 拦截并注入反检测脚本
3. 考虑对快手 API 直接请求（而非通过页面渲染）
4. 抖音：需用户登录态才能获取视频作者信息

### 五、URL 不可猜测 / 反遍历 / 405 主动拒绝（6 个平台 → 第二轮补充测试结论）

首次测试中 6 个平台被标记为 "URL 无效"。第二轮补充测试各尝试了 6~8 个候选 URL，
最终将这些平台分为三类：

#### 5A. 405 主动拒绝（反爬行为）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **虎扑 BBS** | 生活资讯 | `bbs.hupu.com/*` 全部返回 **405** | 首页 `www.hupu.com` 可正常访问(200)，但 BBS 子域名统一返回 405。**这是明显的主动反爬行为**，不是 URL 无效。 |

**说明**：虎扑首页 `www.hupu.com` 能从 headless 浏览器正常加载（截图 4.6MB），
但 BBS 板块 `bbs.hupu.com` 的所有路径（包括首页、帖子、不同 ID）全部返回 HTTP 405。
这种针对子域名的精确封锁，表明虎扑 BBS 对非浏览器流量有主动拒绝策略。

**v0.3 改进**：`page_access.inspect_http_response()` 新增了 405 的专门处理，
返回 `HTTP_405_ACCESS_RESTRICTED`（不再是之前通用的 `HTTP_{code}`），明确提示
"页面拒绝当前访问方式"。

**建议方案**：
1. 通过 `page.route()` 修改请求头，模拟真实浏览器
2. 使用非 headless 模式
3. 通过移动端 `m.hupu.com` 访问（返回 200，但内容需进一步验证）

#### 5B. URL 反遍历 / 时效性限制（反爬行为）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **网易新闻** | 生活资讯 | 首页 `163.com` 可访问(✅200)，但 6 个不同文章 ID 全部返回 **404** | 文章 URL 不可通过 ID 枚举猜出，可能是网易的**反遍历保护机制** |
| **搜狐视频** | 图文视频 | 首页 `tv.sohu.com` 可访问，但所有具体视频 URL 返回 404/502 | 视频 URL 具有时效性，旧视频可能已下线 |
| **小红书笔记** | 图文视频 | 首页 ✅`assets_ready`，但 6 个相邻 explore ID 全部返回 "笔记不存在" | explore ID 不可顺序猜测，可能是**哈希/随机生成**的反遍历设计 |

**说明**：
- **网易新闻**：首页可正常访问，但猜测的 6 个网易号文章 ID 全部返回 404。文章 ID 可能包含时间戳或校验位，无法通过枚举获得有效 URL。这既是防盗链也是反遍历措施。
- **小红书**：首页完整可用(`assets_ready`)，但 explore 页面的 note ID 是编码后的哈希值，无法通过递增 ID 找到有效笔记。需要从首页/搜索发现真实的 note ID。
- **搜狐视频**：具体视频 URL 编码格式不明，且旧视频可能已下线。

**v0.3 改进**：
- **小红书**：新增 `include_patterns=(r"/explore/", r"/discovery/item/")`，使 explore 路径能正确匹配平台路由。但因 note ID 无效，最终路由仍因重定向上报 `ROUTE_UNSUPPORTED`。
- **搜狐视频**：新增 `include_patterns=(r"/v/",)`，但旧 URL 格式已不匹配。

**建议方案**：
1. **网易新闻**：改为从首页或搜索页通过 Playwright 提取文章链接，而非直接猜测 article ID
2. **小红书**：从首页发现页提取真实 note ID，或通过搜索接口获取
3. **搜狐视频**：确认搜狐视频业务是否仍在运营

#### 5C. 页面可加载但提取器解析不足（非反爬，需改进提取逻辑）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **搜狐新闻** | 生活资讯 | 首页和文章页均可访问(200)，截图正常(64KB~1MB)，但返回 `REQUIRED_FIELDS_MISSING` | 页面 DOM 存在但 `ContentParser` 未匹配到提取规则 |
| **凤凰新闻** | 生活资讯 | 首页可访问(200, 截图1.7MB)，但 6 个不同 article ID 返回**相同截图**(133KB) | `c/xxx` 路径格式不是有效文章 URL，或所有路径指向同一兜底页 |

**说明**：
- **搜狐新闻**：页面能被 Playwright 正常加载并截图，但 `ContentParser` 无法从中提取 `author_name` 和 `published_at`。可能需要增加新的 DOM 选择器规则。
- **凤凰新闻**：6 个不同 `c/xxx` 格式的 URL 返回完全相同的截图(133KB)，说明该路径格式不是正确的文章 URL。正确的文章 URL 需要从首页解析获取。

**建议方案**：
1. **搜狐新闻**：检查 `platform_catalog.py` 中搜狐的选择器，可能需要更新 DOM 选择器
2. **凤凰新闻**：同网易新闻，从首页通过 Playwright 提取真实文章链接

## 反爬机制汇总矩阵

| 反爬类型 | 检测方式 | 被封锁的平台 | 拦截特征 | v0.3 改进 |
|----------|---------|-------------|---------|-----------|
| Webdriver 检测 | `navigator.webdriver` / `window.chrome` | **知乎、贴吧** | 直接 403 | 错误消息更友好 |
| 登录墙 | 检查 Cookie/Session | **拼多多、天猫、淘宝、1688、京东、微博、微信视频号、爱奇艺** | 重定向到登录页 | 新增 URL 模式 + 文本双重检测 |
| CAPTCHA | 行为分析 + 频率检测 | **百度百家号、优酷** | 弹出验证码页面 | 新增 URL + captcha 文本标记检测 |
| JS 沙箱 / 空页面 | `navigator` 属性 / 内容长度 | **西瓜视频、今日头条、百家号、懂车帝** | 内容不渲染 / 空页面 | 新增 `EMPTY_RENDERED_PAGE` / `CONTENT_UNAVAILABLE` |
| API 直接响应 | 非浏览器特征请求 | **快手** | 返回 JSON 而非 HTML | 新增 `UNEXPECTED_API_RESPONSE` 识别 |
| **子域名主动拒绝** | 按子域名 + HTTP 方法过滤 | **虎扑 BBS** (`bbs.hupu.com`) | 统一返回 405 | 新增 `HTTP_405_ACCESS_RESTRICTED` |
| **URL 反遍历** | 文章 ID 含校验位/时间戳 | **网易号**、**小红书 note ID** | 猜测的 ID 全部返回 404 | 新增 `CONTENT_NOT_FOUND` / `CONTENT_UNAVAILABLE` |
| 重定向到首页 | 路径对比 | **土豆、1688** | 具体内容页被重定向到平台首页 | 新增 `CONTENT_REDIRECTED_TO_HOME` |
| 提取器不足 | DOM 结构变化 | **搜狐新闻**、**闲鱼** | 页面能加载但提取不到必要字段 | 未改进（需更新选择器） |

## 推荐解决方案

### 短期方案（不修改核心架构）

| 措施 | 适用平台 | 实施难度 | 预期效果 |
|------|---------|---------|---------|
| **注入反检测脚本** | 知乎、贴吧、今日头条、西瓜视频 | 低 | 可能绕过基础 headless 检测 |
| **增加页面稳定等待时间** | 抖音、快手、今日头条 | 低 | 提高 JS 渲染完成率 |
| **拦截第三方资源提速** | 搜狐新闻、凤凰新闻 | 低 | 减少超时（v0.3 已解决搜狐超时） |
| **增加超时时间配置** | 搜狐新闻 | 低 | v0.3 已不再需要（搜狐已正常加载） |
| **从首页/搜索页提取真实文章链接** | **网易新闻、凤凰新闻、小红书** | 中 | 获取有效文章 URL，绕过反遍历 |
| **通过移动域名访问** | 虎扑 BBS | 低 | 绕过 BBS 子域名的 405 封锁 |
| **安装 rapidocr-onnxruntime** | 纯图片页面 | 低 | 启用 v0.3 OCR 后备能力 |

### 中期方案（需 GUI 配合）

| 措施 | 适用平台 | 实施难度 | 预期效果 |
|------|---------|---------|---------|
| **主导航拦截**（`page.route()` 屏蔽广告/统计） | 所有平台 | 低 | 提高加载速度，减少超时 |
| **用户提供 storage_state** | 需要登录的所有平台 | 中（需 GUI 支持） | 解决绝大多数登录墙问题 |

| 措施 | 说明 | 风险 |

### 备注
1. **合规边界**：本项目只采集用户有权处理的公开信息。任何反爬措施不得包含绕过验证码、付费墙、账号权限的行为。登录态必须由用户显式提供。
2. **测试数据时效性**：部分测试 URL（如网易新闻、搜狐视频）可能已失效，实际使用时应使用用户输入的有效 URL。
3. **B站和小红书首页成功经验**：B站是当前唯一可完整抓取视频页的平台；小红书首页也可完整访问。这两个平台对 headless 浏览器较为友好，可作为开发调试的主要目标。
4. **"URL 无效"不等于"没有反爬"**：第二轮多 URL 测试表明，有些平台看似"URL 无效"实则是主动反爬（如虎扑 BBS 405）或反遍历（如网易新闻、小红书 note ID 不可顺序猜测）。判断是否为反爬，需要测试多个候选 URL + 首页可达性综合评估。
