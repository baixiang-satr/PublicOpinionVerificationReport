# 反爬机制检测报告与解决方案

> **文档版本**: v0.2  
> **测试日期**: 2026-07-28  
> **测试范围**: 模板 8 个工作表中 6 个适用 URL 抓取的工作表，共 30 个平台  
> **测试工具**: Playwright Chromium headless (`TaskConfig(headless=True)`)  
> **测试方法**: 每个平台选取一个公开 URL，通过 `CrawlEngine` 执行完整爬取流程（访问→解析→路由→截图）  
> **第二轮补充测试**: 对首次失败的 6 个平台，各尝试 6~8 个候选 URL 以确认是否为 URL 失效 vs 反爬机制

## 各平台反爬措施分类

### 一、Headless 检测 + 403 直接封锁（2 个平台）

这些平台通过 JS 检测 `navigator.webdriver`、`window.chrome` 等 Headless 特征，直接返回 HTTP 403。

| 平台 | 归属工作表 | 测试状态码 | 行为描述 | 反爬手段 |
|------|-----------|-----------|----------|----------|
| **知乎** | 微博博客 | 403 | 拒绝 headless 浏览器访问 | `navigator.webdriver` 检测 + UA 分析 |
| **百度贴吧** | 微博博客 | 403 | 拒绝 headless 浏览器访问 | 百度统一反爬系统 |

**特征**：
- 请求没有经过重定向直接返回 403
- 响应体极小，无有效内容
- 属于服务器端主动拒绝

**建议方案**：
1. 将 401/403 明确标为访问受限，不进行高频重试
2. 用户确认有权访问后，改用可视模式或显式提供自己的登录态
3. 仍被拒绝时保留诊断结果，不把错误页或空白页作为证据

### 二、重定向到登录/访客页面（8 个平台）

这些平台不直接拒绝访问，而是将未登录用户重定向到登录页面，导致页面解析失败。

| 平台 | 归属工作表 | 最终页面 | 反爬/限制手段 |
|------|-----------|---------|---------------|
| **拼多多** | 电商平台 | `login.html` | 未登录重定向到登录页 |
| **天猫** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **淘宝** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **1688** | 电商平台 | `login.taobao.com` | 未登录重定向到淘宝统一登录 |
| **京东** | 电商平台 | 页面导航到风控页 | JS 执行过程中页面跳转到风险控制页 |
| **微博** | 微博博客 | `passport.weibo.com/visitor` | 重定向到访客页，可看到"微博访客"但无内容 |
| **微信视频号** | 图文视频 | `channels.weixin.qq.com/login` | 视频号助手需微信扫码登录 |
| **爱奇艺** | 图文视频 | 首页（而非视频页） | 视频页需登录，降级到首页 |

**特征**：
- HTTP 状态码为 200，但内容是登录/访客页面
- 截图可以看到登录界面
- 引擎正确识别状态为 `needs_review` / 缺少必要字段

**建议方案**：
1. 用户显式提供 `storage_state`（导出已有登录态的 Cookie）
2. 在 GUI 中提供"可视化登录"选项（非 headless 模式手动登录一次）
3. 登录仍失败时记录最终 URL 和 `LOGIN_REQUIRED`，由用户核对账号权限

### 三、CAPTCHA / 验证码拦截（3 个平台）

这些平台在检测到可疑流量后弹出图形验证码或滑动验证码。

| 平台 | 归属工作表 | 最终页面 | 验证码类型 |
|------|-----------|---------|-----------|
| **百度百家号** | 公众号 | `wappass.baidu.com/static/captcha/tuxing.html` | 百度统一图形验证码 |
| **优酷** | 图文视频 | `v.youku.com/.../punish` | 优酷 x5sec 滑动验证码 |
| **西瓜视频** | 图文视频 | JS 未执行（前端检测） | 字节跳动前端反爬（JS 沙箱检测） |

**特征**：
- 状态码 200，页面为验证码 UI
- 截图可看到验证码界面
- 优酷的验证码通过 URL 中的 `punish` 参数标识
- 百家号的验证码路径包含 `captcha/tuxing`

**建议方案**：
1. 可视模式下由用户本人完成验证码，并在有界等待后重新检查页面
2. 验证未完成或再次触发时标记 `CAPTCHA_REQUIRED`
3. 验证页不得截图进入模板，也不得自动提交、破解或购买验证码服务

### 四、JS 沙箱/前端数据保护（4 个平台）

这些平台在前端使用 JS 加密、动态加载或检测脚本，使得 headless 浏览器无法正常渲染内容。

| 平台 | 归属工作表 | 行为描述 |
|------|-----------|---------|
| **抖音** | 图文视频 | 页面加载后视频数据需登录，截图仅有 UI 框架 |
| **快手** | 图文视频 | 返回 JSON 而非 HTML（API 响应） |
| **西瓜视频** | 图文视频 | 页面含 JS 沙箱检测代码，内容不渲染 |
| **今日头条** | 生活资讯 | 页面提示"需要允许该网站执行 JavaScript" |

**特征**：
- HTTP 状态码为 200
- 页面 HTML 中无有效内容（仅有 JS 加载器或空框架）
- 截图显示空白或 loading 状态
- 引擎返回 `REQUIRED_FIELDS_MISSING`

**建议方案**：
1. 增加 `page_stabilize_milliseconds` 等待 JS 执行
2. 识别 JavaScript 提示、空壳页面和 JSON/API 响应，避免误判成功
3. 仅在平台公开、稳定且授权范围明确时增加正式 API 适配器
4. 抖音：需用户登录态才能获取视频作者信息

### 五、URL 不可猜测 / 反遍历 / 405 主动拒绝（6 个平台 → 第二轮补充测试结论）

首次测试中 6 个平台被标记为 "URL 无效"。第二轮补充测试各尝试了 6~8 个候选 URL，
最终将这些平台分为三类：

#### 5A. 405 主动拒绝（反爬行为）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **虎扑 BBS** | 生活资讯 | `bbs.hupu.com/*` 全部返回 **405** | 首页 `www.hupu.com` 可正常访问(200)，但 BBS 子域名统一返回 405。**这是明显的主动反爬行为**，不是 URL 无效。 |

**说明**：虎扑首页 `www.hupu.com` 能从 headless 浏览器正常加载（截图 4.6MB），
但 BBS 板块 `bbs.hupu.com` 的所有路径（包括首页、帖子、不同 ID）全部返回 HTTP 405。
这种针对子域名的精确封锁，表明虎扑 BBS 对非浏览器流量有主动拒绝策略。

**建议方案**：
1. 将 405 标记为访问方式受限，不自动切换域名或伪造请求头
2. 用户提供平台正常浏览流程取得的真实内容 URL
3. 可视模式仍无法访问时保留待处理状态，不生成主截图

#### 5B. URL 反遍历 / 时效性限制（反爬行为）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **网易新闻** | 生活资讯 | 首页 `163.com` 可访问(✅200)，但 6 个不同文章 ID 全部返回 **404** | 文章 URL 不可通过 ID 枚举猜出，可能是网易的**反遍历保护机制** |
| **搜狐视频** | 图文视频 | 首页 `tv.sohu.com` 可访问，但所有具体视频 URL 返回 404/502 | 视频 URL 具有时效性，旧视频可能已下线 |
| **小红书笔记** | 图文视频 | 首页 ✅`assets_ready`，但 6 个相邻 explore ID 全部返回 "笔记不存在" | explore ID 不可顺序猜测，可能是**哈希/随机生成**的反遍历设计 |

**说明**：
- **网易新闻**：首页可正常访问，但猜测的 6 个网易号文章 ID 全部返回 404。文章 ID 可能包含时间戳或校验位，无法通过枚举获得有效 URL。这既是防盗链也是反遍历措施。
- **小红书**：首页完整可用(`assets_ready`)，但 explore 页面的 note ID 是编码后的哈希值，无法通过递增 ID 找到有效笔记。需要从首页/搜索发现真实的 note ID。
- **搜狐视频**：具体视频 URL 编码格式不明，且旧视频可能已下线。

**建议方案**：
1. **网易新闻**：要求输入从正常浏览流程取得的真实文章 URL，不猜测 article ID
2. **小红书**：要求输入真实笔记 URL；首页和搜索页不作为目标内容证据
3. **搜狐视频**：核对视频是否仍在线及 URL 是否来自当前平台页面

#### 5C. 页面可加载但提取器解析不足（非反爬，需改进提取逻辑）

| 平台 | 归属工作表 | 测试结果 | 判断依据 |
|------|-----------|---------|---------|
| **搜狐新闻** | 生活资讯 | 首页和文章页均可访问(200)，截图正常(64KB~1MB)，但返回 `REQUIRED_FIELDS_MISSING` | 页面 DOM 存在但 `ContentParser` 未匹配到提取规则 |
| **凤凰新闻** | 生活资讯 | 首页可访问(200, 截图1.7MB)，但 6 个不同 article ID 返回**相同截图**(133KB) | `c/xxx` 路径格式不是有效文章 URL，或所有路径指向同一兜底页 |

**说明**：
- **搜狐新闻**：页面能被 Playwright 正常加载并截图，但 `ContentParser` 无法从中提取 `author_name` 和 `published_at`。可能需要增加新的 DOM 选择器规则。
- **凤凰新闻**：6 个不同 `c/xxx` 格式的 URL 返回完全相同的截图(133KB)，说明该路径格式不是正确的文章 URL。正确的文章 URL 需要从首页解析获取。

**建议方案**：
1. **搜狐新闻**：检查 `platform_catalog.py` 中搜狐的选择器，可能需要更新 DOM 选择器
2. **凤凰新闻**：补齐平台选择器，并要求用户提供真实文章 URL

## 反爬机制汇总矩阵

| 反爬类型 | 检测方式 | 被封锁的平台 | 拦截特征 |
|----------|---------|-------------|---------|
| Webdriver 检测 | `navigator.webdriver` / `window.chrome` | **知乎、贴吧** | 直接 403 |
| 登录墙 | 检查 Cookie/Session | **拼多多、天猫、淘宝、1688、京东、微博、微信视频号、爱奇艺** | 重定向到登录页 |
| CAPTCHA | 行为分析 + 频率检测 | **百度百家号、优酷** | 弹出验证码页面 |
| JS 沙箱 | `navigator` 属性检测 | **西瓜视频、今日头条** | 内容不渲染 |
| API 直接响应 | 非浏览器特征请求 | **快手** | 返回 JSON 而非 HTML |
| **子域名主动拒绝** | 按子域名 + HTTP 方法过滤 | **虎扑 BBS** (`bbs.hupu.com`) | 统一返回 405 Method Not Allowed |
| **URL 反遍历** | 文章 ID 含校验位/时间戳 | **网易号**、**小红书 note ID** | 猜测的 ID 全部返回 404/页面不存在 |
| 提取器不足 | DOM 结构变化 | **搜狐新闻**、**凤凰新闻** | 页面能加载但提取不到必要字段 |

## 推荐解决方案

> 本节是根据测试现象形成的项目实施决定。报告早期提出的自动化隐匿、验证码破解、代理轮换、移动域名规避和自动搜索真实链接不纳入项目；它们会扩大权限边界，也会削弱证据链的可审计性。

### 已实施方案（2026-07-28）

| 措施 | 实现位置 | 行为 |
|------|---------|------|
| 统一受限页诊断 | `src/tools/page_access.py` | 识别登录、验证码、JS 空壳、JSON/API、内容失效、跳回首页和空页面 |
| 截图质量门禁 | `src/crawler/engine.py` | 受限页在解析/截图前停止，防止错误页面进入证据包 |
| HTTP 精确分流 | `src/crawler/engine.py` | 401/403/405 待处理，404/内容失效失败，429/5xx 有界重试 |
| 用户自有登录态 | `src/screenshot/browser.py`、GUI | 显式导入 Playwright storage state，不记录到日志或 ZIP |
| 可视人工接力 | `src/tools/page_access.py`、GUI | 非后台模式下给用户 90 秒完成登录/验证码，完成后重新检查 |
| 内容 URL 约束 | `src/crawler/platform_catalog.py` | 小红书、搜狐视频、网易、凤凰、虎扑等首页不再被当作内容证据 |
| 平台提取增强 | `src/crawler/platform_catalog.py` | 补齐搜狐、凤凰、网易、头条的标题、正文、作者和发布时间选择器 |

### 明确不实施

- 不隐藏 `navigator.webdriver`，不伪造浏览器指纹或请求头。
- 不自动破解图形验证码、滑块或平台风控挑战。
- 不通过代理轮换规避封禁或频率限制。
- 不自动搜索、猜测内容 ID 或切换域名来绕过 URL/子域名限制。
- 不连接未经用户明确授权的现有浏览器、Cookie 或账号会话。

## 项目工具与集成位置

- `src/tools/page_access.py`：可复用的访问状态检查和可视人工处理等待。
- `src/crawler/engine.py`：导航后调用访问工具，再执行平台路由、解析和截图。
- `src/screenshot/browser.py`：创建隔离 context，并仅加载用户显式选择的 storage state。
- `src/crawler/platform_catalog.py`：集中维护内容页路径和字段选择器。

### 备注
1. **合规边界**：本项目只采集用户有权处理的公开信息。任何反爬措施不得包含绕过验证码、付费墙、账号权限的行为。登录态必须由用户显式提供。
2. **测试数据时效性**：部分测试 URL（如网易新闻、搜狐视频）可能已失效，实际使用时应使用用户输入的有效 URL。
3. **首页不等于内容证据**：B站有效视频页可完整抓取；小红书、网易、凤凰、虎扑等首页即使能够访问，也不能代替用户输入内容页的取证结果。
4. **"URL 无效"不等于"没有反爬"**：第二轮多 URL 测试表明，有些平台看似"URL 无效"实则是主动反爬（如虎扑 BBS 405）或反遍历（如网易新闻、小红书 note ID 不可顺序猜测）。判断是否为反爬，需要测试多个候选 URL + 首页可达性综合评估。
