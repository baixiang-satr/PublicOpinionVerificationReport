# 下一阶段开发说明：字段完整性与个人主页证据可信化

## 1. 阶段目标

本阶段在不要求重新验证淘宝、天猫、1688、京东、抖音、微博和头条登录态的
前提下，解决两类核心问题：

1. 已经拿到页面或接口数据时，尽可能完整、准确地填入标题、昵称、发布时间
   和信息内容。
2. 个人主页截图从“能生成”升级为“身份正确、页面类型正确、无遮挡、可人工
   使用”的证据。

继续遵守以下不可变约束：

- 输入多少条，工作簿就保留多少条；失败记录也必须有原始 URL 对应行。
- 登录页、空白页、删除页、风控页和身份不匹配页不得作为截图。
- 不拼接两个横向页面；只保留经过验证的主页主体区域。
- OCR、图片下载、主页截图属于可选增强，失败或超时不得推翻已成功的正文
  抓取和主截图。
- 固定模板不新增列。没有独立标题列的工作表，应在“信息内容”内用明确标签
  保存标题。

## 2. P0：个人主页证据验收管线

### 2.1 建立结构化判定结果

新增 `AuthorEvidenceDecision`，建议放在
`src/screenshot/author_evidence.py`：

```text
candidate_url
candidate_source
expected_name
expected_id
detected_name
detected_id
page_type
access_state
overlay_state
capture_region
accepted
rejection_code
```

每张主页截图都必须先形成判定结果，再决定是否写入 ZIP。质量报告分别统计：

- `author_url_candidates`
- `author_pages_opened`
- `author_identity_validated`
- `author_clean_screenshots`
- 各拒绝码数量

### 2.2 身份校验改为“头部强证据优先”

修改 `src/screenshot/author_shooter.py`：

1. 主页头部昵称或账号 ID 存在时，只与头部强证据比对。
2. 头部显示其他人时，即使导航、侧栏、推荐卡片中出现预期作者名也必须拒绝。
3. 账号 ID 匹配优先于昵称；昵称做标准化后允许合理的前后缀差异。
4. 没有正文作者名和账号 ID 时，不得声称“身份已验证”；只能在页面类型明确
   为个人主页且来源 URL 是平台专用解析结果时进入人工复核。
5. 将检测出的主页名称和 ID 写入质量报告，便于人工追溯。

本轮已经完成第 1、2 点的基础修正，并增加“网易导航文字不能放行新华社主页”
回归测试。下一步要把检测结果持久化，而不是只在异常信息中出现。

### 2.3 页面类型分类

新增主页类型分类器，至少区分：

- `PERSON_PROFILE`
- `MEDIA_PROFILE`
- `STORE_PROFILE`
- `COMMENT_USER_PAGE`
- `CORPORATE_SECTION`
- `ARTICLE_PAGE`
- `LOGIN_OR_CHALLENGE`
- `DELETED_OR_EMPTY`
- `UNKNOWN`

修改 `src/screenshot/author_asset.py` 和
`src/crawler/author_profile_urls.py`：

- 只有个人、媒体或店铺主页可以进入截图。
- 评论用户页必须确认它就是正文作者，否则拒绝。
- `/csr/`、普通新闻、帮助中心、企业介绍等栏目不得作为个人主页。
- 候选 URL 必须记录来源：平台 JSON、正文作者链接、JSON-LD、DOM 或推导。
  通用 JSON-LD 的组织/网站链接不能冒充作者主页。

建立真实回归样例：

- 047/048：正文作者“网易”，主页头部“新华社”，应拒绝。
- 050：正文作者“第一现场”，评论用户“热血之刃”，应拒绝。
- 051：正文作者“壮壮科普”，主页头部“观察者网”，应拒绝。
- 057/058：美团企业社会责任栏目，应判为 `CORPORATE_SECTION`。
- 052/054：应识别为可接受主页。

### 2.4 弹窗、遮挡和登录组件

在截图前增加 `dismiss_profile_overlays()`：

1. 仅点击语义明确的关闭按钮、取消按钮或 Cookie 接受/拒绝按钮。
2. 点击后再次检查遮挡面积和登录提示。
3. 遮挡主体区域超过 15%，或登录弹窗仍覆盖昵称/账号/作品区时，返回
   `AUTHOR_OVERLAY_BLOCKED`，按无截图处理。
4. 不自动输入密码、验证码或扫码登录。

用 025、026 的 B 站主页作为回归样例：身份可以通过，但弹窗未清理时不得
进入最终 ZIP。

### 2.5 截图区域与横向拼接治理

优先截取已验证的主页主体 DOM：

1. 主页头部资料区。
2. 头部下方首屏作品/动态区。
3. 必要时向下扩展，但宽度只使用同一个内容容器。

若页面本身包含左右两栏：

- 使用 DOM 容器边界截取，不做像素横向拼接。
- 对左右两侧分别运行登录/空白/有效内容判定。
- 一侧是登录页、另一侧是正常主页时，只截正常主页容器。
- 无法可靠分离时返回 `AUTHOR_SPLIT_LAYOUT_UNSAFE`，按无截图处理。

修改 `src/screenshot/page_shooter.py`，让截图元数据记录最终
`capture_region` 和裁剪原因。

### 2.6 ZIP 前二次审计

在 `src/export/staging_assets.py` 增加作者附件审计：

- 文件必须有对应的 `AuthorEvidenceDecision(accepted=True)`。
- 被拒绝或未验证的 `主页.jpg` 不得进入工作簿附件列和 ZIP。
- 发现孤立、身份错配或遮挡截图时，删除 staging 副本中的引用并写入待补录
  报告；不得修改源模板。

## 3. P0：字段完整性和来源关联

### 3.1 平台专用数据对象必须与当前 URL 绑定

优先修改：

- `src/crawler/structured_data.py`
- `src/crawler/extractors/catalog.py`
- `src/crawler/extractors/generic.py`
- `src/crawler/field_resolver.py`

每个候选字段除了值、来源、置信度，还要记录：

- `content_id`
- `source_path`
- `request_url`
- `candidate_scope`（正文、评论、推荐、导航、作者资料）

只有 `content_id` 与当前 URL/页面主对象一致，或候选明确位于文章主容器时，
才能覆盖标题、昵称、时间和正文。评论摘要、推荐卡片和侧栏文章不得覆盖完整
正文。本轮第 44 条正文由 342 字恢复到 8,005 字，需把这一保护做成固定回归
测试。

### 3.2 平台专用解析器优先级

在用户自行维护登录态之后，按下列顺序开发，不再重复做登录动作：

1. 抖音、今日头条、西瓜：优先页面内嵌状态、XHR/Fetch 主对象。
2. 微博：正文状态对象、用户对象、可信创建时间。
3. 百家号：文章状态和作者资料对象；可选图片 OCR 独立限时。
4. 快手：视频/图文主对象，避免把 API 错误 JSON 当正文。
5. 网易、凤凰、搜狐：作者链接必须与文章 source/author 对象关联。
6. 电商：商品标题、店铺名、商品详情主对象；不把通用平台宣传语当商品正文。

为每个平台保存脱敏后的 HTML/JSON 固件测试，不依赖实时网络完成回归。

### 3.3 标题在固定模板中的落位

模板只有电商和公众号有独立标题列。其他工作表统一导出为：

```text
【标题】……
【正文】
……
【图片文字】
……
```

如果标题已经自然出现在正文开头则不重复。对应修改
`src/export/row_mapper.py`，并增加所有工作表的映射测试。

### 3.4 时间可信度

时间候选分为：

- 平台接口/内嵌 JSON 原始发布时间
- `time[datetime]` 或正文主区域时间
- 页面相对时间，经抓取时区换算
- 不可信的页面更新时间、版权年份、抓取当前时间

禁止用当前抓取时间补“发布时间”。质量报告应包含原始字符串、解析后时间、
时区和来源。当前 26 条非空时间是下一轮不可回退基线。

### 3.5 昵称和组织名称

把“作者昵称”“公众号名称”“店铺名称”“媒体来源”“网站品牌”分开建模，
最后按工作表语义映射：

- 不允许用网站品牌自动覆盖正文作者。
- 没有个人作者时，媒体账号可作为昵称，但必须标记来源。
- 通用导航词、栏目标题和发布时间不得作为昵称。

当前昵称/店铺/公众号名称非空 19 条是下一轮不可回退基线。

## 4. P0：图片 OCR 的准确性与限时

### 4.1 正文图片绑定

OCR 候选只接受：

- 位于文章/商品/帖子主容器内；
- 与当前内容对象同一 `content_id`；
- 尺寸满足阈值且不是头像、Logo、二维码、表情、广告、推荐卡片。

记录图片在正文中的顺序，OCR 结果按原顺序合并。不要识别页面全屏截图中的
浏览器导航、任务栏或安全提示。

### 4.2 图片格式和下载失败回退

对于 AVIF、SVG、懒加载、Canvas 和受鉴权保护图片：

1. 优先通过当前浏览器上下文请求。
2. 下载失败时对目标图片元素直接截图，再交给 OCR。
3. 单张图片失败不得终止其余图片。
4. 下载/OCR 使用有限并发，总增强预算建议 40–50 秒。

### 4.3 OCR 文本质量

- 去除重复行、页眉页脚、纯按钮和低信息噪声。
- 只有新增语义文本时才追加 `【图片文字】`。
- 有正文图片且所有图片都确认 `NO_TEXT` 时，才写
  `【纯图片内容：图片中未识别到文字】`。
- OCR 进程崩溃时最多重启一次，并保留已完成图片结果。

### 4.4 可选增强不能降级主任务

本轮已经增加独立可选增强超时。下一阶段必须补集成测试：

- 主正文和主截图成功；
- OCR 图片下载永久挂起；
- 任务仍为 `exported` 或 `needs_review`，而不是 `failed`；
- 工作簿保留已取得正文和主截图；
- 错误列表仅增加 `OPTIONAL_ENRICHMENT_TIMEOUT`。

第 18 条百家号作为在线复验目标，但不要为此重新验证登录态。

## 7. 验收标准

### 7.1 正确性硬门槛

- 输入 68 条，工作簿必须正好 68 条，URL 多重集合完全相等。
- 登录页、空白页、删除页、风控页和企业栏目页进入截图的数量为 0。
- 个人主页身份错配数量为 0。
- 横向拼接截图数量为 0。
- 可选增强超时导致核心成功记录降级的数量为 0。
- ZIP 中未被工作簿引用的截图数量为 0。

### 7.2 字段基线

在登录态条件不比本轮更差时：

- 标题提取不少于 39 条，目标不少于 44 条。
- 昵称/店铺/公众号名称不少于 19 条，目标不少于 25 条。
- 发布时间不少于 26 条，目标不少于 32 条。
- 信息内容不少于 39 条，目标不少于 44 条。
- 工作簿正文总字符不少于 40,717。
- 任何字段下降都必须在差异报告中列出证据编号和原因。

### 7.3 主页截图

- “干净可交付截图”的人工抽检准确率必须达到 100%。
- 分母使用“身份和页面类型可确认的候选主页”，不得用全部 URL 稀释指标。
- 第一阶段目标：可确认候选主页的干净截图覆盖率达到 60%。
- 登录弹窗无法关闭时宁可不截图，也不能输出被遮挡证据。

### 7.4 稳定性

- 取消任务 5 秒内恢复 UI。
- 浏览器驱动断连不产生无限 `socket.send()` 重试。
- OCR 子进程超时可终止、可重启，不阻塞主进程退出。
- 仅重新导出时不得启动浏览器。
- 选定重试时未选记录必须从断点复用。
